## What the composer actually is

- **Formula — real and correct.** [gates.py:25-48](../../flowforge/composer/gates.py:25) `compose(a1,a2,gate_input,w,b)` computes `sigmoid(w*I+b)` ([gates.py:16-18](../../flowforge/composer/gates.py:16), clipped to ±30) and blends with per-point broadcast over trailing tensor dims, with finite/shape/`g∈[0,1]` asserts. Probe vs an independent oracle: `maxdiff=0.00e+00`; `sigmoid(0)=0.5`; deterministic on repeat. Only scalar `w,b` and a single scalar invariant `I` — no vector `w·I` over I1..I5.
- **Penalty — computed, then dropped.** [gates.py:13](../../flowforge/composer/gates.py:13) `GATE_DL_PENALTY_BITS=16.0`; `compose` returns it per call and [evaluate.py:18-22](../../flowforge/composer/evaluate.py:18) accumulates it (probe: 3 modules → 32 bits, `n_gates=2`). But [engine.py:15-17](../../flowforge/elegance/engine.py:15) `description_length(n_nodes, constants)` has no gate parameter, and [round.py:57-62](../../flowforge/orchestrator/round.py:57) builds champion DL as `description_length(complexity(expr), [])` — constants empty, gates impossible. The penalty never reaches `pick_champion` ([engine.py:36-40](../../flowforge/elegance/engine.py:36), the correct 3%-margin/min-DL rule from Phase 2). Free gating is forbidden by the plan; in the selection path, gating is currently free because it is absent (P4-05).
- **No gate fitting.** `compose()` and `evaluate_composition(..., w, b)` merely take `w,b` as inputs. There is no optimizer anywhere: no `fit_gates` string in `flowforge/`, no `scipy/minimize/grid` in the composer, and the tool registry ([registry.py](../../flowforge/agents/tools/registry.py)) registers only `search_cards` and `fit_constants`. The spec's Composer role ("Muse Spark 1.3 plus gate fitting", tool `fit_gates`) has a schema ([schemas.py:83-89](../../flowforge/agents/schemas.py:83) `CompositionPlan{modules, gates:list[dict]}`) and an 8-line prompt ([composer.yaml](../../prompts/composer.yaml)), but no tool and no caller (P4-03, P4-09).
- **No joint composition.** [evaluate.py:19-21](../../flowforge/composer/evaluate.py:19) loops `compose(modules[i], modules[i+1], gate_inputs[i], w, b)` — independent pairwise blends sharing one `(w,b)`, returning only score scalars. No composite field, expression or closure is ever produced, so nothing could be sent to the ladder, solver, codegen or library (P4-04).
- **Evaluation bug (probe-proven).** `errors = [mean((p-t)**2) for p,t in zip(preds, targets)]` ([evaluate.py:23](../../flowforge/composer/evaluate.py:23)) silently drops the last target because `len(preds)=len(modules)-1`. Probe demo: 3 zero modules vs targets `[0, 0, 99]` → `worst_error=0.0, best_single_worst=9801.0, beats_single=True`. The RP4 signal fires spuriously and the last training flow is invisible. Comparands also mismatch: `preds[i]` (blend of modules i,i+1) is scored against `targets[i]` while `single_errors[i]` scores `modules[i]` against `targets[i]`. Scoring is raw mean-MSE max, not the ladder's SST-normalised minimax ([ladder.py:17-21](../../flowforge/ladder/ladder.py:17)) (P4-06, P4-07).

## Verdicts on cross-phase findings (Phase-4 slice)

- **D5 reproducibility — partly applicable, currently moot, DECISION_NEEDED when wired.** The composer math is deterministic (probe `deterministic_D5core` PASS: byte-identical repeat), so a fitted `(w,b)` + recorded module hashes would reproduce exactly.
